# The Research Desk

This project is a web application for searching and chatting with your own knowledge base. Similar in spirit to [Andrej Karpathy's knowledge bases](https://x.com/karpathy/status/2039805659525644595?s=20) or google's notebook LM.
The code is from late 2024 to mid 2025 but I still think there are a few things that are novel about it and potentially worth sharing. 

I would say the **core difference in this approach compared to what else is out there is it exposes semantic search results directly to the user**. The same semantic search that is used by the AI agent is also directly exposed to the user.
But it is not a traditional search engine. The search is using AI at every step. 
- PDF parsing via [marker](https://github.com/datalab-to/marker). Marker does handle text in images with OCR and it's layout engine identifies the distinct blocks of content. It uses gemini to render tables and figures as searchable text. Images of the tables and figures are displayed directly in the search results.
- Hybrid of BM25 and semantic search
- Every search result has a dynamically generated title generated by an LLM
- Documents are organized into a hierarchy of categories. You can search all categories or just some categories. Machine learning is used to recomend categories based on your search query. Your selection of categories scopes both search and agen'ts retrieval in chat.
- Every document and category has an LLM generated description
- Video and audio are transcribed and searchable. Clicking a result seeks directly to that moment in the built-in player. 
- Math rendering for formulas found in PDFs
- The user can click a button to jump directly from a search result to the page in the pdf in the built in pdf viewer. The specific block of text with the excerpt is highlighted.

The way the research desk exposes the semantic search results to the user seems obvious and yet I have seen no applications that offer a search experience which is meaningfully different from the usual keyword search. Even applications like Cursor that use semantic search under the hood, still give users the same old exact match search from vscode. There is a reason that semantic search is commonly used for AI agents but most user facing applications still use traditional search: It is because the semantic search results still have terrible aesthetics for human consumption. In order to make search results that are presentable to humans the research desk has to do things differently:
- I took notes on the outputs from many different pdf parsing solutions and found that while marker was the best it is still not perfect. So the research desk has gemini do a second pass to correct the outputs of marker by looking at a screenshot of the pdf page.
- While most RAG systems use a fairly large chunk size, the research desk chunks at the sentence level so that the search results can show precisely the relevant sentences without irrelevant sentences that happen to be in the same chunk. Since chunking at the sentence level means that the usual embedding methods would be missing surrounding context, the research desk uses Voyage AI's late chunking which is a different paradigm that eliminates the tradeoff between small and large chunks. The embedding model sees the entire document at once so that it has full context but outputs embeddings for each individual chunk.
- Since all the sentence chunking methods I tried(including ones using ML) have edge cases that produce ugly results, the research desk uses gemini to do agentic chunking. Using gemini for this feels like cracking a nut with a sledgehammer but the other solutions had ugly edge cases which aren't acceptable for human consumption.
- The way traditional search bolds keyword matches, the Research Desk bolds semantically similar words by measuring cosine similarity of each word in the result to the query.


The search results shown to the user are tightly integrated with the experience in the chat with the agent:
**From search results view to agent chat**: You can add a search result to the context of the agent (similar to cmd+L in cursor) 
**From agent chat to search results view**: Every search query the agent does in chat shown to the user and clickable. When the user clicks on of these search queries they are taken to the search results for that query to see the same search results the agent saw. 

The search results the agent sees have a unique id associated with each excerpt, table and figure so that the agent can cite any excerpt, table or figure in it's response. If the user clicks on a citation that takes them to the page in the pdf in the built in pdf viewer. 
Cited tables and figures render inline in the response, alongside any Mermaid diagrams the agent generates. The agent can respond visually, not just verbally.
